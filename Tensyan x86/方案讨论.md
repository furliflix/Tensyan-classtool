# Tensyan x86 —— 32 位版方案讨论

> 这份文档回答两个问题：**32 位版应该怎么开发？还需要用 C# 吗？**
> 结论不是拍脑袋来的：下面每一条都附了本机实测数据，并且我已经把 32 位版**编译出来跑通了**。

---

## 一、先把"32 位"问清楚：你要的其实是哪一种？

"做 32 位版"背后可能是三个完全不同的目标，技术路线差别很大：

| 目标 | 说明 | 该怎么做 |
| --- | --- | --- |
| **A. 能在 32 位 Windows 上跑** | 机房/学校老机器，装的是 32 位 Win7 / Win8.1 / Win10 | 必须是 32 位进程，且目标机要有**可用的运行时**。Win7 上只有 .NET Framework 4.8 这条路（.NET 8 不支持 Win7） |
| **B. 一个 exe 在 32/64 位系统都能跑** | 不想分发两个包 | 用 `AnyCPU`（64 位系统上原生 64 位、32 位系统上原生 32 位），不必强制 x86 |
| **C. 只是嫌 x64 版体积大 / 想更"兼容"** | 没有 32 位机器 | 位数帮不上忙，应该去做单文件/精简/签名，而不是换架构 |

**⚠️ 关键分叉**：如果目标里有 **Windows 7**（哪怕 64 位），.NET 8 直接出局，只能走 .NET Framework 4.8。
如果目标只有 Win10 1903+ / Win11，那 x64 版已经够用，32 位只是"锦上添花"。

---

## 二、本机实测：可选的路线其实只有一条

我把所有相关工具链和运行时都查了一遍：

| 检查项 | 结果 | 对选型的影响 |
| --- | --- | --- |
| x64 .NET 8 桌面运行时 | ✅ 8.0.31 已装 | x64 版继续可用 |
| **x86 .NET 运行时** | ⚠️ 只有 6.0.36 和 10.0.12，**没有 8.0.x** | 现在做 `net8` x86 框架依赖版，**本机都跑不起来** |
| NuGet 缓存里的运行时包 | ❌ 只有 `runtime.win-x64`，**没有 `win-x86`** | **离线做不出 x86 自包含**（需要联网下载运行时包） |
| 原生编译器 `cl / gcc / clang / fpc / dcc32` | ❌ 一个都没有 | C++ / Delphi / Free Pascal 路线**离线无法开工** |
| .NET Framework 4.8 参考程序集 | ✅ 在 | **net48 编译立即可用** |
| 现有源码规模 | 28 个文件 / 428 KB | 移植量可控 |

> 结论：**离线可用的 32 位路线只有一条 —— .NET Framework 4.8 + `PlatformTarget=x86`。**

## 三、还继续用 C# 吗？—— 是，但要换运行时，不是换语言

### 为什么不用 C++ / Delphi / Free Pascal

- **要重写整个 UI**：Tensyan 的界面是自绘的（Fluent 卡片、圆角、动画、DPI 缩放、导航栏、随机点名动画），换成 MFC/Qt 等于从零再做一遍，而且要把 27 项自检、U 盘密钥、Excel 导出全部重写；
- **本机没有编译器**，离线连"hello world"都编不出来；
- 换来的收益只有"exe 从 333 KB 变成 ~500 KB"——没有意义。

### 为什么不用 .NET 8 x86

- 目标机必须额外安装 **x86 版** .NET 8 Desktop Runtime（注意：x64 运行时**不能**给 32 位进程用，得单独装一份）；
- 本机没有 x86 运行时、缓存里也没有 win-x86 包，**离线自包含发布做不出来**；
- 体积会涨到 ~90 MB（自包含）。

### 为什么 .NET Framework 4.8 是正解

| 维度 | net48 x86 | net8 x86 自包含 |
| --- | --- | --- |
| 支持的系统 | **Win7 SP1 / 8 / 8.1 / 10 / 11（32 与 64 位通吃）** | 仅 Win10 1607+（不支持 Win7） |
| 目标机前置 | **无**（Win10 1903+/Win11 自带 4.8；老系统装一次 4.8 即可） | 需装 x86 运行时或带 90 MB |
| 本机离线能否构建 | ✅ 可以 | ❌ 不行（缺 win-x86 包） |
| 产物大小 | **333 KB**（+1 个 200 字节 .config） | ~90 MB |
| 安装器复用 | ✅ 现有安装器本来就是 net48 | 需另做 |
| 代价 | 不能直接用 `System.Text.Json` 等新库、个别 WinForms 新 API 要绕 | 无 |

**所以答案是：继续用 C#，把 32 位版做成 `net48 + x86`。** 一份源码、两个目标框架，靠 `#if NETFRAMEWORK` + 两个兼容垫片维持。

## 四、实测移植成本：已经做完了，0 编译错误

我没有停在"理论上可行"，直接在新目录里建了 `TensyanX86.csproj`（共享 x64 版全部源码），一步步把编译和运行打通：

### 4.1 编译过程

| 阶段 | 编译错误 | 原因 / 处理 |
| --- | --- | --- |
| 直接把源码扔进 net48 | 10 个 | 全是同一个源头：`System.Text.Json`（离线下拿不到这个 NuGet 包） |
| 加 `System.IO.Compression` 引用 + 写离线 JSON 垫片 | 8 个 | 剩 `Application.SetHighDpiMode`、`TextBox.PlaceholderText`（net8 专属 WinForms API） |
| 加 `UI/WinCompat.cs`（EM_SETCUEBANNER 代替占位提示、DPI 感知分支） | **0 个** | ✅ 编译成功 |

### 4.2 实际改动了 3 个文件（其余源码一字未动）

1. **`Core/Store.cs`**：把 `Json` 类用 `#if !NETFRAMEWORK` 包住（32 位版用下面的垫片）；
2. **`Tensyan x86/Compat/JsonCompat.cs`（新增，约 320 行）**：用反射实现一个**输出格式与 System.Text.Json 完全一致**的 JSON 读写——
   PascalCase 属性名、枚举写成字符串、DateTime 用 ISO 8601 往返格式（并像 STJ 一样去掉小数秒末尾的 0）、
   缩进 2 空格、不序列化字段、非 ASCII 不转义、读入时属性名大小写不敏感；
3. **`UI/WinCompat.cs`（新增）** + `Widgets.cs` / `Program.cs` 各 1 行调用：跨框架的占位提示与 DPI 感知。

### 4.3 验证结果（全部实测）

| 验证项 | 结果 |
| --- | --- |
| PE 头 Machine | `0x014C` = **I386，真 32 位进程** ✅ |
| 产物 | `TensyanX86.exe` **333 KB** + `.exe.config` |
| 自检（U盘签名 / PBKDF2 / Excel zip / 权限探测 / JSON 读写） | **27 / 27 通过** ✅ |
| 界面功能自检（按身份能否添加学生、单窗口切换） | **8 / 8 通过** ✅ |
| 界面渲染（net48） | 与 x64 版**截图一致**：28 张学生卡、头像、字体、DPI 无差异 ✅ |
| **跨版本数据互通** | x64 写的数据(3151 行) → x86 读入重写 → **逐行完全一致**；x86 写的 28 人数据 → x64 读回同样一致 ✅ |

> 也就是说：**老机器装 32 位版、新机器装 64 位版，可以直接共用同一个 `data` 文件夹**，
> 32 位版也能读写原来 x64 版的数据，反之亦然。

## 五、32 位特有的坑（设计上要预先处理）

1. **内存上限 ~2 GB**（32 位进程）：积分记录目前限制 5 万条 ✅；导出/备份要做流式，避免一次性把巨型备份读进内存；不建议在 32 位版里加载超大历史。
2. **注册表重定向**：32 位进程写 `HKLM\SOFTWARE\...` 会落到 `WOW6432Node`。卸载登记项在"应用和功能"里依然可见，但**安装器和程序必须同为 x86**，否则 64 位卸载器可能看不到 32 位的登记项（HKCU 不受重定向影响）。
3. **文件系统重定向**：默认安装目录要用 `Environment.SpecialFolder.ProgramFilesX86`（即 `C:\Program Files (x86)\Tensyan`），不要用 `ProgramFiles`。
4. **单实例互斥体**：如果 x86 与 x64 版共用同一个 `data` 目录，**应共用同一个互斥体名**，否则两个进程可能同时写坏数据；反之若想让它们并存，就必须分开数据目录。这一条要在发布说明里写清楚。
5. **数据格式必须与 x64 版一致**：已做到（第 4.3 节实测），否则换版本会读不出班级数据。
6. **PBKDF2 在 32 位下稍慢**：仍走后台线程 + 6 秒兜底超时 ✅。
7. **高 DPI**：net48 靠**清单** `dpiAware` + `SetProcessDPIAware()`（已加进 `app.x86.manifest`）。
8. **单文件分发**：net48 没有"单文件发布"。要么一个文件夹（推荐，配合安装器），要么用 ILMerge/Costura 把依赖合并（本项目没有第三方依赖，其实只有一个 exe + 一个 .config，已经很干净）。

## 六、建议的交付形态

```
Tensyan  x86/                      ← 32 位版工程（本目录）
├─ TensyanX86.csproj               ← net48 + x86，共享 ..\Tensyan 的源码
├─ app.x86.manifest                ← asInvoker + dpiAware
├─ Compat/JsonCompat.cs            ← 离线 JSON 垫片（格式与 STJ 一致）
├─ build-x86.ps1                   ← 一键构建（可选装 ILMerge 做单文件）
├─ dist/                           ← 交付：TensyanX86.exe + .exe.config
└─ 预览截图/                        ← 32 位版实际渲染截图
```

- **安装包**：直接复用现有 `Installer\TensyanSetup`（它本来就是 net48！）→ 只加 `-p:PlatformTarget=x86` 和 x86 负载，就能输出 `TensyanSetup-x86.exe`，默认目录改成 `%ProgramFiles(x86)%\Tensyan`，注册表改写 `WOW6432Node` 视图；
- **发行策略**：x64 版给新机器，x86 版给老机器，**数据可互换**；同一台机器建议只装一个；
- **命名**：`dist/` 里目前叫 `TensyanX86.exe`。正式发行时建议仍叫 **`Tensyan.exe`**，靠文件夹名（`Tensyan x86`）区分，避免用户困惑 —— 这点等你定。

## 七、需要你确认的三件事

1. **目标系统到底是什么？** 32 位 Win7 / 32 位 Win10 / 还是"只要能兼容 32 位就行"？
   （如果目标里有 Win7，那 net48 是唯一解；如果只有 Win10+，其实 x64 版就够了，32 位版只是保险）
2. **要不要再做一版 `AnyCPU` 单包**（一个 exe 在 32 位系统上就是 32 位、64 位系统上就是 64 位）？
   它和 x86 版源码完全相同，只是编译参数不同，成本几乎为零，适合"只发一个包"的场景。
3. **是不是现在就把它做成完整交付**：x86 安装包 + 全套截图 + 更新说明书/README + 版本号？
   我预估：安装包半天内可完成（复用现有安装器），其余是文档与截图工作。

### 附：本目录里的可复现命令

```powershell
# 32 位版（net48 / x86）
dotnet build "Tensyan x86\TensyanX86.csproj" -c Release

# 自检（务必给带空格的路径加引号，或用 cmd）
"Tensyan x86\bin\Release\net48\TensyanX86.exe" --selftest "F:\temp\selftest"
"Tensyan x86\bin\Release\net48\TensyanX86.exe" --uitest   "F:\temp\uitest"

# 用真实数据出界面截图（验证与 x64 版数据互通）
"Tensyan x86\bin\Release\net48\TensyanX86.exe" --shot "F:\temp\shots" --data "F:\temp\data" --demo
```
